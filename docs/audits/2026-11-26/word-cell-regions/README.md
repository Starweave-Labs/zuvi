# W026 区域表格浏览器测试准备

本目录目前只包含真实 DOCX 输入和测试准备资料，尚未运行浏览器，不代表 W026 完整验收完成。

`regions-source.docx` 是用 JSZip 从已归档的区域公式 DOCX 生成的原生 ZIP。`source-reference.docx` 保存参考输入原字节，来源及 SHA-256 在 `fixture.json` 中。正文、默认页眉和默认页脚分别包含独立表格与区域标记；每张表格为一个非固定高度行、两个单元格，首格短文本加粗，第二格含三段文字。A4 统一页边距为 40mm，表格宽度留有余量，避开本批仍在调整的固定行高度预算。

三张表格分别使用不同的默认四侧边距、直接边距、垂直与水平对齐、单元格间距。间距记录物理间隙磅值，原生 `tblCellSpacing` 写入其十分之一磅单位值；内边距使用二十分之一磅单位。页眉首格有上边距显式零，左边距直接值独立于表格默认值。

测试代码是 `e2e/office-studio-word-cell-regions.spec.ts`，计划执行：

- 实际导入文件，双击切到页眉和页脚，通过 ZUVI 九宫格、直接／默认边距和间距控件修改；取消保留原数据，一次撤销恢复本区域全部属性，重做恢复完整修改。
- 两次真实导出及重开；解析主文档和关系指向的页眉／页脚原生 XML，确认属性、文字与加粗格式在各区域独立保持。
- 正文只读时关闭编辑入口；在弹窗草稿中通过文档站的实际 ZUVI 只读开关模拟宿主权限变化，验证禁用与取消。该动作触发开关的正常处理函数，不植入或伪造 Editor／文档模型。
- 浅色、暗色以及两种主题的 320px 弹窗实际输入、选择和取消，检查边界及水平溢出；最终导出证明这些草稿没有写入原文件模型。

运行后才会生成两轮 DOCX、原生 XML、截图和结果 JSON。本准备阶段仅检查 ZIP 可读、XML 完整、区域关系指向及 TypeScript 语法；没有启动浏览器、构建、Registry 或全仓检查。
